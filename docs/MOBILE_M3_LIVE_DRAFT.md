# Baseball Mobile M3 — Live Draft mobile redesign

Base: M2 checkpoint `2021111` on `mobile/m1-foundation` (descends from `cafe437`).
Widths: 360 / 390 / 430 (phone) and 1280 (desktop reference). Scope: Live Draft
Setup, Ready and active-draft layout on phones. Presentation only: no draft,
timer, queue, recommendation, roster, persistence or multiplayer logic changed,
and no draft state duplicated.

## 1. Architecture found

- The Live Draft page is one long Streamlit script inside `streamlit_app.py`.
  The active view interleaves several `@st.fragment` regions (clock/heartbeat,
  recommendations, queue, board). Fragment identity is
  `hash(func + delta_path + extra)`, so **moving or wrapping a fragment call, or
  inserting new siblings above one, changes its identity** and breaks its
  in-place reruns. A Python-side reorder was therefore ruled out.
- The desktop layout is `rec_col | board_col` columns. Below 640px Streamlit
  stacks them, so on a phone the On the Clock banner and Manual Draft sat
  under the full recommendation column (multiple full rec cards first).
- Solo has two modes. **Mode A** is the minimal live-clock view that ends in
  `st.stop()` and offers Quick Queue only. **Mode B** is the full view. The
  Solo clock banner is in-page `st.html`. The multiplayer banner is a
  `components.html` iframe whose `srcdoc` contains `live-draft-on-clock`.

## 2. Approach: CSS order tiers on the phone (new `live_draft_mobile_layout.py`)

Existing elements get stable class hooks from keyed `st.container(key=…)`
wrappers around **single, non-fragment** elements. Wrapping one element keeps
the delta indices of later siblings. On phones only (`@media (max-width: 640px)`),
the page's flex column and its stacked columns are flattened with
`display: contents`, and each item is placed by `order` tier:

| Tier | Order | Content |
|---|---|---|
| Quick nav (M2) | -100 | current page + jump select |
| Alerts | -97 | top-level `st.alert`s (errors/warnings stay visible) |
| Clock | -95 | On the Clock banner + timer (Solo markup and multiplayer iframe) |
| Status | -93 | pick / round / room status pills |
| Action | -90 | Manual Draft panel (`ldr-m-action`, `ldr-m-action-early`) |
| Controls | -85 | Control Center (`ldr-m-controls`) |
| Recommendations | -50 | Team Needs, rec column, rec cards as a horizontal swipe strip |
| Board | -20 | Queue, Board, Rosters |
| Rec tables | -10 | Rankings and summaries |
| Chat | 5 | room chat |

The clock and action rules come last on the same base selectors, so they win
specificity ties against the tier rules. No rule nests `:has()`: browsers drop
the whole rule, selector lists included. The phone duplicates (the in-page
"📡 Live Draft Room" title, the brand caption, the multiplayer room-summary and
room-header blocks that repeat the banner) are hidden only inside the active
page. Style-only element containers are collapsed so they don't cost a 16px
flex gap each.

**Desktop is unchanged**: every rule is inside the phone media query. Structure
and first-control position at 1280 are identical to M2.

**Accessibility note**: CSS `order` changes visual order only. DOM and tab
order are still the desktop order (rec column before the board). Screen reader
and keyboard users get the desktop sequence on phones.

## 4. Verification setup

- **Real active drafts** were reached through the committed render path. Solo
  and a two-browser multiplayer room were each run Setup → Ready → Start →
  picks. No DOM mocks.
- The Ready gate needs `data/tb_probe/prewarm_unified_pool.parquet`. That file
  is gitignored and is generated by the committed prewarm script. A fresh
  worktree cannot reach Ready without it.
- **Persistence checks:**
  - A fresh session restores the in-progress draft.
  - Leaving via the quick nav and returning keeps the same pick, and the
    clock keeps running.
  - Refreshing mid-draft stays on Live Draft at the same pick.
  - The `?active_page=Live%20Draft%20Room` deep link works in a fresh session.

## 5. M1 / M2 fixes found while verifying M3

- **CommonMark style-block bug.** A `<style>` HTML block ends on the line
  containing `</style>`. A second `<style>` on that same line was rendered as
  visible text and never applied. Every appended style block now starts on a
  new line (test added).
- **Quick-nav label overlap (M2).** Forcing `display:block` on phones collapsed
  the label to ~7px, and Streamlit's -16px markdown margin pulled the select
  over it. Native flex is kept and the margin is reset.
- **Quick nav cost two 16px gaps on every desktop page (M2).** The styles moved
  inside the keyed container, and the container's layout wrapper is hidden on
  desktop.
- **Desktop Quick Guide showed only its header (M2).** Current Chromium hides
  closed disclosure content through `::details-content`, so a separate desktop
  rule now reopens it.
- **Blank select values in 2-up wrap rows (M1).** The wrap-row `button {width:100%}`
  rule stretched the select chevron over the value. It is now limited to
  `stBaseButton-*`.

## 6. Observed issues already present before M3 (not changed)

- **The multiplayer On the Clock banner is missing in some states.** It was
  A/B tested on unmodified M2 code and on M3 code with the same room:
  - On both, the guest's banner shows while the pick deadline is valid.
  - On both, the host's banner is absent at the same state.
  - On M2 code, the banner disappeared exactly when the deadline expired and
    the draft auto-advanced.

  M3 behaves the same as M2.
- **The Solo timer re-arms on refresh or a new session** (observed 1153 →
  1171/1188 s). This is server-side timer logic that M3 doesn't touch. It was
  not re-measured on M2.
- **Mode A has no manual draft.** During a live Solo clock only Quick Queue is
  offered. This is committed behavior. Uncommitted Live Draft work in the main
  worktree appears to address it. That work was deliberately **not** imported.

## 7. Tests

- **Mobile and nav tests:** the M1, M2 and M3 mobile tests plus nav restore
  give 63 passed.
- **Regression set:** 179 Live Draft, timer, queue, recommendation,
  persistence and multiplayer files, run on M3 and on the M2 checkpoint
  `2021111` in a temporary detached worktree, with the same `data/tb_probe`
  fixture and runtime data parked. Both have 89 failing test cases. The
  failures already exist on M2: these tests track the main worktree's newer,
  uncommitted Live Draft behavior.
- **The only differences** are two timing-sensitive tests:
  - `test_ten_consecutive_optimistic_picks` also fails in isolation on M2.
  - `test_cloud_delay_matrix_150ms_through_8s` is flaky under load on M2.

  **M3 adds no regressions.**
